# Your Unitfield site

A Next.js (App Router) site on the Unitfield storefront API: your homes for rent, a listing page for each, an inquiry
form, customer sign-in, and a link to your hosted account. It was generated by `create-unitfield-site`; everything in it is
yours to change.

```bash
npm run dev      # http://localhost:3000
npm run build
npm start
npm run typecheck
```

## Set it up

1. In Unitfield open **Website > Developers**, create a **Test** key and copy it into `.env.local` as
   `UNITFIELD_PUBLISHABLE_KEY` (the scaffolder created the file from `.env.example`).
2. Add the address you develop on to the key's **Allowed origins**: `http://localhost` works on any port with a test key.
   The browser talks to the API directly only from the inquiry form; pages are fetched by the server and need no origin.
3. `npm run dev`.

The publishable key is public by design: it can read your public listings, send an inquiry and start a sign-in, nothing more. Keep the
other values in `.env.local` (git ignores it) and set them in your host's environment settings in production.

## What is here

| Path | What it does |
| --- | --- |
| `app/page.tsx` | Home: your newest homes. |
| `app/listings/page.tsx` | All homes, with a search form that lives in the URL, and cursor paging. |
| `app/listings/[listingId]/page.tsx` | One home: photos, facts, the **Apply** link, an inquiry form. |
| `app/contact/page.tsx` | A general inquiry form. |
| `app/auth/*` | Customer sign-in: `sign-in` and `callback` (OIDC authorization code + PKCE) and `sign-out`. |
| `app/api/unitfield/webhook/route.ts` | Optional: drops the cached API reads when Unitfield tells you something changed. |
| `lib/storefront.ts` | The SDK client. Reads are cached for 60 seconds under one tag. |
| `lib/session.ts` | The sealed httpOnly cookie that holds the customer's tokens. |
| `components/` | The header, footer, listing card and inquiry form. |

The listing markup uses the headless parts of `@unitfield/react` (`ListingGrid`, `ListingPrice`, `ApplyButton`, ...), which
bring no styles; the look is in `app/globals.css`.

## Apply and account

**Apply** links to the hosted apply page on your Unitfield domain (`applyUrl` of the listing). The applicant continues
there: the draft, the sign-in and the submission all live in Unitfield. The listing page shows a note instead of the button
when a home is not taking applications.

**My account** links to the hosted account (`hostedUrls.accountUrl` from `/site`). It has its own sign-in on your Unitfield
domain: signing in on this site does not sign the person in there, and the other way round.

## Customer sign-in

Off until you set `UNITFIELD_CLIENT_ID` and `UNITFIELD_SESSION_SECRET`.

1. Register `{UNITFIELD_SITE_URL}/auth/callback` under **Redirect URIs** of your key (for a test key, `http://localhost:3000/auth/callback`).
2. Set `UNITFIELD_CLIENT_ID` to the OAuth client id of that key's sign-in client.
3. Set `UNITFIELD_SESSION_SECRET` to at least 32 random characters (`openssl rand -base64 32`).

The server keeps the customer's tokens in a sealed httpOnly cookie, so the browser never sees them. The header shows the
email from the ID token. The starter does not call any API as the customer; when you do, refresh the tokens in a route handler
or a Server Action, never while a page renders: Next cannot write cookies there, and Unitfield rotates refresh tokens, so a
refresh whose result is dropped signs the customer out.

## Inquiries

The form posts from the browser to the Unitfield API with your publishable key, so the limits count the visitor and not your
server. The API requires a Cloudflare Turnstile token with every inquiry and verifies it itself. Without `TURNSTILE_SITE_KEY`
a development build sends a placeholder token (accepted only by an API that has Turnstile switched off) and a production build
shows your contact details instead of the form. A rejected token is answered like an accepted inquiry and nothing is created,
so do not rely on inquiries in production until the Turnstile site key for your domain is set up with Unitfield.

## Webhooks

Set `UNITFIELD_WEBHOOK_SECRET` to the signing secret of an endpoint that points at
`https://your-site.example/api/unitfield/webhook`. A verified `listing.*` or `site.*` event revalidates the cached API reads.
